# Nof1 native Android

This is an independent Kotlin and Jetpack Compose app, not a WebView or React
Native container. The existing Expo client and backend are untouched. Five tabs
retain the source navigation: Today, Peptides, Log, Protocols, Profile. Experiments
are reachable from Profile and from the experiment quick-log action.

Versions were verified against published Maven metadata and source artifacts.
The Gradle wrapper was generated by Gradle's official `wrapper` task using the
official distribution's SHA-256, which is pinned in wrapper properties. No
handmade wrapper JAR is used. AGP 9 supplies built-in Kotlin support.

References: [Clerk Android](https://clerk.com/docs/android),
[Convex Android](https://docs.convex.dev/client/android/overview), and
[Clerk integration source](https://github.com/clerk/clerk-convex-kotlin/tree/v0.15.0).
The published bridge requests a default session token, so this client uses
Convex's documented `AuthProvider` extension with Clerk
`GetTokenOptions(template = "convex", skipCache = true)` instead. The SDKs own
native session storage and token refresh. Application code never persists or
logs JWTs, passwords, or secret keys.

## Configuration lanes

### Cloud

Copy `native.properties.example` to ignored `native.properties`, then supply the
Clerk **publishable** key and the matching Convex deployment URL. Alternatively,
provide `NOF1_CLERK_PUBLISHABLE_KEY` and `NOF1_CONVEX_URL` as build environment
variables. Environment variables take precedence. These are client-visible
configuration values, not server credentials. Never put Clerk secret keys or
Convex deployment/admin keys in a mobile build.

The cloud application ID is `com.nof1.experiments.nativeapp`. Enable the existing
Clerk instance's Native API and register the side-by-side application namespace
and package identity before authenticated testing. The existing Convex backend
must trust that Clerk issuer and the `convex` JWT audience/template. Do not deploy
or edit those services as part of building this client. Missing configuration
shows an explicit setup error and does not activate local mode.

`NOF1_ENABLE_ACCOUNT_DELETION` defaults to `false` to keep development/device
verification non-destructive. After owner approval, setting it to `true` exposes
the double-confirmed account deletion flow: `account:deleteMyData` runs before
Clerk's native `User.delete()`. Partial failure is explicitly reported. This
flow must not be exercised against a live account during routine verification.

### Local development

Select the `localDemoDebug` variant explicitly. It uses application ID
`com.nof1.experiments.nativeapp.local` and displays a persistent **LOCAL
DEVELOPMENT** banner. Enter a development profile name to access that profile's
app-private JSON file. Files contain synthetic tracking records, never Clerk
credentials. File names are identity hashes; storage failures remain visible and
do not replace records with an empty or successful result. Android backup is
disabled. Leaving a profile destroys its view-model store; re-entering the same
profile reloads its records. A different profile has a separate file.

Local success is not evidence of a real Clerk or Convex integration. The app
never imports Expo's unscoped local arrays or falls back to this repository after
a cloud failure.

## Build and verification

Run JVM and Compose/Robolectric tests with SDK 37 and JDK 17 on a supported
test host: Linux x86-64, or macOS arm64/x86-64. Robolectric 4.16.1 does not support
Linux ARM, so the current Revyl Android build image cannot run these UI tests.
Do not skip them or change their graphics mode to make an ARM run pass.

```bash
cd native/android
./gradlew :app:testLocalDemoDebugUnitTest :app:lintLocalDemoDebug
```

Build the installable APK on the authorized Android cloud builder:

```bash
cd native/android
./gradlew :app:assembleLocalDemoDebug
```

APK: `native/android/app/build/outputs/apk/localDemo/debug/app-localDemo-debug.apk`.

For real integration verification, supply the cloud configuration and run the
cloud-flavor tests on the supported test host:

```bash
cd native/android
./gradlew :app:testCloudDebugUnitTest :app:lintCloudDebug
```

Then build the cloud flavor on the authorized Android cloud builder:

```bash
cd native/android
./gradlew :app:assembleCloudDebug
```

APK: `native/android/app/build/outputs/apk/cloud/debug/app-cloud-debug.apk`.

No production signing configuration is supplied. Release signing and billing
registration require separate owner-approved configuration. Build directories,
private configuration, APKs, signing files, and local tooling are ignored.
Do not run paid builds/devices with an unverified Revyl organization credential.

The platform-local `.revyl/config.yaml` provides a `local-demo` remote-build
profile targeting the isolated **Nof1 Native Android** app container. From this
directory, run `revyl build --profile local-demo --platform android --remote` only
with the intended Nof1 credential selected. This profile runs lint and packages
the APK; the complete JVM/UI test suite remains a separate required gate on the
supported test host described above. It does not inherit the Expo auth-bypass hook or change the root
Expo PR-review profile. Do not publish this local build context with
`revyl config push` as a replacement for the repository's Expo configuration.

For a source-only configuration check (does not produce a mobile binary):

```bash
cd native/android
./gradlew help
./gradlew :app:dependencies --configuration localDemoDebugCompileClasspath
```

The app bundles `../shared/` assets directly, preserving all 71 catalog entries.
Regenerate shared resources using `native/scripts/export-shared.mjs` from the
repository root. Legal disclosures are copied exactly from the maintained Expo
screen by `node native/android/scripts/export-legal.mjs`; native capability
limitations are displayed separately, rather than silently changing legal text.

## Implemented and remaining verification

Core native paths include authentication, identity-scoped cloud queries and
mutations, persistent explicit local development, catalog search/details,
dose/metric/stack tracking, protocols and adherence, experiments and actual
metric entries, profile, legal, and authoritative subscription access display.
Mutation forms wait for the write result, disable duplicate taps, and never
blindly retry ambiguous writes. Free experiment capacity remains server-owned.

Store purchase/restore, Whop connection, health import, notification scheduling,
profile editing, and export are not implemented in this
side-by-side client. Their screens disclose the unavailable state; no health,
purchase, or deletion success is simulated. Completing those capabilities needs
their native integrations and appropriate provider registration, not a fake
backend response. Account deletion is implemented but disabled by default for
development safety and has not been exercised against an external account.

A successful Gradle configuration check is not a compiled APK, UI verification,
or a cloud-write proof. Record the actual authorized build/device results against
`../shared/scenarios.json` separately and keep local and cloud evidence distinct.
